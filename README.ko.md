# aiLog

🌐 **한국어** | [English](./README.md)

> **대화는 끝나도, 의미는 남아야 한다.**

aiLog는 LLM 대화를 위한 장기 기억 아키텍처입니다. 단순한 대화 저장 시스템이 아니라, 대화에서 *의미*를 추출하고 구조화하여 세션을 넘어 되살려내는 시스템입니다.

---

## 문제

LLM과의 모든 대화는 처음부터 시작됩니다.

과거의 아이디어는 사라집니다. 맥락은 매번 다시 설명해야 합니다. 몇 시간에 걸쳐 발전시킨 통찰도 세션이 끝나는 순간 잃어버립니다. LLM을 많이 쓸수록, 잃는 것도 많아집니다.

이건 UX 문제가 아닙니다. 구조적인 문제입니다.

---

## aiLog가 다른 이유

대부분의 메모리 시스템은 대화 원문을 저장하고 키워드로 검색합니다.

aiLog는 다른 접근을 취합니다: **메시지가 아니라 의미를 저장합니다.**

각 대화는 구조화된 기억 계층으로 처리됩니다 — 원시 로그에서 의미 기반 에피소드, 장기 기억까지 — 그래서 꺼내오는 것은 오래된 텍스트 더미가 아니라 *지금 대화에 필요한 의미*입니다.

설계 원칙:

> *기억을 꺼내온다는 것은 과거 대화를 보여주는 것이 아니다. 지금 대화에 필요한 과거의 의미를 잠깐 불러오는 것이다.*

---

## 기억 아키텍처

aiLog는 대화 데이터를 네 가지 의미 계층으로 구성합니다:

| 계층 | 설명 |
|---|---|
| **RawLog** | 원본 메시지 로그 — 가공 없이 보존되는 진실의 원천 |
| **Gist** | 분절된 원시 로그에서 추출한 압축된 의미 |
| **Episode** | 원시 로그에서 도출된 의미 단위의 대화 묶음 |
| **Long-term Memory** | 세션을 넘어 반복적으로 부상하는 고가치 기억 |

### 백엔드 파이프라인

```
수집 → 분절 → gist 생성 → episode 구성 → 기억 승격 → 검색 → 재주입
```

기억은 수동으로 쌓이지 않습니다 — 능동적으로 형성되고, 승격되고, 미래 대화에 다시 주입됩니다.

---

## 핵심 목표

- 대화를 구조화된 영속적 형태로 저장
- 메시지 단위가 아닌 에피소드 단위로 의미를 추출
- 과거의 아이디어, 결정, 표현을 의미 기반으로 검색
- 검색된 맥락을 LLM 세션에 재주입하여 연속성 확보
- 축적된 기억으로 사용자 개성 모델링을 향해 발전

---

## 의미 기반 검색

대부분의 검색 시스템은 단어를 매칭합니다. aiLog는 *의미*를 매칭합니다.

### 실제로 어떻게 다른가

무슨 말을 했는지, 어떻게 표현했는지 기억하지 않아도 됩니다.

| 찾고 싶은 것 | 검색어 | 키워드 검색 | aiLog |
|---|---|---|---|
| 열용량에 대한 과거 논의 | "비열" | ✅ 정확한 단어만 | ✅ "열 전달", "온도 변화 속도" 등 관련 내용도 찾음 |
| 기억 아키텍처에 대한 아이디어 | "episode" | ✅ 그 단어를 썼을 때만 | ✅ "기억 단위", "대화 덩어리"로 표현했어도 찾음 |
| 한번 썼던 표현 | 비슷하게 바꿔 입력 | ❌ | ✅ 임베딩 유사도로 검색 |

### 작동 원리

aiLog는 원시 메시지를 검색하지 않습니다 — **에피소드**를 검색합니다: 대화 세그먼트에서 추출하고 임베딩한 의미 단위.

```
원시 메시지 → 분절 → gist 추출 → episode 임베딩 → 벡터 인덱스
                                                          ↓
                                                  코사인 유사도 검색
                                                          ↓
                                                  관련 episode 검색
                                                          ↓
                                                  의미를 LLM 컨텍스트에 재주입
```

두 가지 검색 모드가 함께 작동합니다:

- **의미 검색** (pgvector): 키워드가 아닌 의미로 찾음 — 문장 임베딩의 코사인 유사도 활용
- **전문 검색** (PostgreSQL FTS): 정확한 용어, 이름, 표현을 잡아냄

검색은 사용자가 여는 검색창이 아닙니다. *대화 중에 자동으로 발동됩니다* — LLM이 이전 맥락에 대한 자연스러운 참조를 감지하고, 관련된 것만 꺼내옵니다.

## 설계된 프라이버시 — 로컬 우선 아키텍처

대화 데이터는 클라우드 저장소에 절대 닿지 않습니다.

aiLog는 **로컬 우선 원칙**으로 설계되었습니다: 모든 대화 기록은 사용자의 기기에서 저장되고 처리됩니다. 외부로 나가는 데이터는 LLM API에 전송하는 프롬프트뿐 — 이는 LLM을 사용하는 이상 피할 수 없는 것이지, aiLog가 선택한 방식이 아닙니다.

```
내 기기                               외부
─────────────────────────────         ──────────────
 대화 기록                             LLM API
 에피소드          ── 프롬프트 ──▶    (OpenAI 등)
 장기 기억        ◀── 응답 ──
 벡터 인덱스
 (모두 로컬)
```

이를 깔끔하게 구현하기 위해 aiLog는 **MCP (Model Context Protocol)** 를 통합 레이어로 채택합니다. MCP는 저장된 데이터를 제3자 플랫폼을 거치지 않고, 표준화된 방식으로 LLM 제공자와 연결할 수 있게 합니다.

결과: 외부 LLM의 지능, 로컬 시스템의 프라이버시.

## 기술 스택

| 레이어 | 선택 | 이유 |
|---|---|---|
| Frontend | Next.js | 채팅 인터페이스 + 검색 경험 |
| Database | PostgreSQL | 구조화된 대화 저장 |
| Search | pgvector + Full-Text Search | 의미 + 키워드 검색 |
| ORM | SQLAlchemy | 유연한 대화 데이터 관리 |
| 향후 확장 | OpenSearch / Qdrant | 검색 규모가 커질 때 |

스택은 1단계에 맞게 의도적으로 가볍게 구성했습니다. 검색 인프라는 나중에 독립적으로 확장할 수 있도록 아키텍처를 설계했습니다.

## 개발 현황

aiLog는 현재 활발히 개발 중입니다. 현재 집중하는 영역은 에피소드 메모리 레이어와 대화형 검색 — 대화 중 이전 맥락에 대한 자연스러운 참조를 감지하고, 관련된 것만 꺼내오는 것입니다.

## 비전

장기 목표는 단순한 기억 검색이 아닙니다 — **사용자 개성 모델링**입니다.

aiLog가 대화에서 의미를 축적해가면서, 한 사람이 어떻게 생각하는지를 반영하기 시작합니다: 반복되는 주제, 선호하는 표현, 발전하는 아이디어. 시스템은 *무엇을* 말했는지뿐 아니라, *누가* 말하는 사람인지를 학습합니다.
